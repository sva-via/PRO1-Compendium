## 2. One-to-Many Relationships

A one-to-many relationship means:

> One object manages multiple related objects.

Examples:

- a `Notebook` contains many notes
- a `Playlist` contains many songs
- a `GradeList` contains many grades
- a `SchoolClass` contains many students

Example:

![Notebook 1 ---- * PriorityNote](../images/Notebook.png)

One notebook may contain many notes.

---

## 3. Collections Inside Objects

Objects often manage collections internally.

Example:

```java
public class Notebook
{
  private PriorityNote[] notes;
  private int size;
}
```

The notebook object becomes responsible for:

- adding notes
- removing notes
- finding notes
- protecting invariants

The collection itself is usually private.

---

## 4. Arrays versus ArrayList

One-to-many relationships may use:

### Arrays

Example:

```java
private PriorityNote[] notes;
```

Advantages:

- fixed capacity
- explicit size management
- predictable structure

Disadvantages:

- manual resizing
- manual shifting
- more implementation work

---

### ArrayList

Example:

```java
private ArrayList<PriorityNote> notes;
```

Advantages:

- dynamic size
- simpler implementation
- automatic resizing

Disadvantages:

- slightly less control

After Session 9:

- arrays are good when size is fixed
- `ArrayList` is preferred when size changes dynamically

---

## 5. Example: Notebook

Example structure:

```java
public class Notebook
{
  private int size;
  private PriorityNote[] notes;
}
```

The notebook is responsible for managing notes.

The notes should not be manipulated directly from outside.

---

## 6. Adding Objects

Example:

```java
public void addNote(String note)
{
  notes[size] = new PriorityNote(note);
  size++;
}
```

The notebook creates and manages its own note objects.

This is an example of responsibility.

---

## 7. Composition and Responsibility

Example:

```java
notes[size] = new PriorityNote(note);
```

The notebook creates the object itself.

This indicates composition.

Composition means:

- ownership
- lifecycle responsibility
- strong relationship

If the notebook disappears, the note objects disappear with it.

---

## 8. Searching Collections

Collections are often traversed using loops.

Example idea:

```java
public int indexOfMostImportantNote()
{
  for (int i = 0; i < size; i++)
  {
    if (isHighPriorityNote(i))
    {
      return i;
    }
  }

  return -1;
}
```

Looping through collections becomes increasingly important.

---

## 9. Returning Information

Example:

```java
public String getMostImportantNote()
{
  int index = indexOfMostImportantNote();

  if (index > -1)
  {
    return notes[index].getNote();
  }

  return null;
}
```

A method may collaborate with other methods.

Good object-oriented design often builds methods from smaller responsibilities.

---

## 10. Removing Objects

Arrays require shifting.

Example:

```java
public void removeNote(int index)
{
  for (int i = index; i < size - 1; i++)
  {
    notes[i] = notes[i + 1];
  }

  notes[size - 1] = null;
  size--;
}
```

Important ideas:

- shift remaining elements
- clean unused positions
- update size

The object protects its own collection.

---

## 11. ArrayList Simplifies Collection Handling

Example:

```java
private ArrayList<Car> cars;
```

Searching:

```java
for (int i = 0; i < cars.size(); i++)
{
  if (cars.get(i).getMake().equals(make))
  {
    // ...
  }
}
```

`ArrayList` removes much of the complexity of manual array management.

---

## 12. Returning Arrays Safely

Sometimes objects return arrays.

Known size:

```java
Car[] cars = new Car[numberOfCars];
```

Unknown size:

```java
ArrayList<Car> carList =
    new ArrayList<>();
```

Later:

```java
return carList.toArray(cars);
```

Collections can help build result arrays dynamically.

---

## 13. Size versus Capacity

Session 11 revisits an important distinction.

### Size

Actual stored elements.

Example:

```java
size
```

### Capacity

Maximum available storage.

Example:

```java
notes.length
```

Arrays often require both concepts.

`ArrayList` hides capacity management internally.

---

## 14. Responsibility in Collection Classes

The collection owner should manage:

Good:

```java
notebook.addNote("Remember PRO1");
```

Less good:

```java
notebook.getNotes()[0] = note;
```

Objects should protect:

- collection invariants
- collection consistency
- valid state

Responsibility remains central.

---

## 15. Testing Collection Classes

Collections require careful testing.

Example:

```java
@Test void testMostImportantNote()
{
  Notebook notes =
      new Notebook(10);

  notes.addNote("Check email");

  notes.addHighPriorityNote(
      "Make PRO1 exercises");

  assertEquals(
      "Make PRO1 exercises",
      notes.getMostImportantNote());
}
```

Important test areas:

- adding objects
- removing objects
- searching
- empty collections
- boundary cases

## 16. Arrays or ArrayList?

Ask:

### Fixed number?

Example:

```text
Album → Songs
```

Array may fit.

---

### Dynamic number?

Example:

```text
Playlist → Songs
```

`ArrayList` often fits better.

Choose structures based on domain responsibility.

## 17. Collaboration Between Objects

Collection classes collaborate with contained objects.

Example:

```java
notes[index]
    .isHighPriorityNote()
```

The notebook delegates note-related responsibility to the note object.

Objects collaborate rather than doing everything themselves.
