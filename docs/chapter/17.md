# Chapter 17 – GUI (Step 2): Data and Events

## 1. Introduction

Session 17 continues GUI development.

- JavaFX structure
- Stage
- Scene

- controls
- containers
- ViewHandler

Session 17 adds:

> interaction

- press buttons
- enter data

- events

---

## 2. Events

An event happens when the user interacts with the GUI.

Examples:

- clicking a button
- entering text
- selecting data

Example:

```text
User presses button
↓
GUI event occurs
↓
Controller method executes
```

Events make applications interactive.

---

## 3. ViewController Classes

Session 17 introduces:

```text
ViewController
```

Responsibility:

- receive GUI events
- communicate with model
- update GUI components

Example structure:

```text
FXML file
↓
ViewController
↓
Model
```

One controller is usually responsible for one FXML file.

Example:

```text
SimpleGUI.fxml
↓
SimpleGUIController
```

Responsibility remains separated.

---

## 4. FXML and Controller Connection

FXML connects GUI and controller.

Example:

```xml
fx:controller=
"SimpleGUIController"
```

Meaning:

> this GUI uses this controller class

FXML describes:

```text
Layout
```

Controller implements:

```text
Behavior
```

Responsibility stays separated.

---

## 5. fx:id

GUI controls may receive identifiers.

Example:

```xml
<TextField
 fx:id="inputField"/>
```

Example:

```xml
<Label
 fx:id="label"/>
```

The controller accesses controls through identifiers.

Example idea:

```java
private TextField inputField;

private Label label;
```

The controller can now:

- read values
- update values

---

## 6. Event Methods

FXML connects controls to methods.

Example:

```xml
<Button
 onAction=
 "#buttonPressed"/>
```

Meaning:

> call method:

```java
buttonPressed()
```

when the button is pressed.

Example flow:

```text
Button press
↓
Event occurs
↓
buttonPressed()
↓
Update GUI
```

Events connect interaction and behavior.

---

## 7. Controller Responsibility

Good responsibility:

Controller:

```text
Read GUI values
```

Controller:

```text
Ask model
```

Controller:

```text
Update GUI
```

Less good:

```text
Controller performs domain logic
```

Example:

Less good:

```java
buttonPressed()
{
  // calculate reservations
}
```

Better:

```java
buttonPressed()
{
  model.reserve(...);
}
```

The model remains responsible.

---

## 8. Access to Model Data

GUI should access model through model responsibility.

Example questions:

```text
Who creates a reservation?
```

Model.

---

```text
Who knows vehicle availability?
```

Model.

---

```text
Who finds customers?
```

Model.

The GUI should ask:

```java
model.getCustomer(phone)
```

Not:

```java
// GUI searches customers itself
```

Responsibility remains central.

---

## 9. Model Interface

Session 14 introduced interfaces.

GUI should access:

```text
Model interface
```

Example:

```java
Customer getCustomer(
    String phone);
```

Example:

```java
Vehicle getVehicle(
    String registrationNumber);
```

The controller depends on:

```text
Model
```

not:

```text
ModelManager
```

Loose coupling remains important.

---

## 10. Example Event Flow

Conceptual flow:

```text
Button pressed
↓
Controller receives event
↓
Controller reads input
↓
Controller asks model
↓
Model updates objects
↓
Controller updates GUI
```

Example:

```text
Customer phone entered
↓
Search button
↓
model.getCustomer(phone)
↓
Show customer name
```

GUI coordinates.

Model remains responsible.

## 11. TableView

Session 17 introduces:

```text
TableView
```

TableView displays collections visually.

Example:

```text
+----------------------+
| Name    | Grade      |
+----------------------+
| Ann     | 12         |
| Bob     | 7          |
| Carl    | 10         |
+----------------------+
```

TableView often displays:

- model collections
- search results
- lists of objects

GUI becomes presentation.

Model remains storage.

Applications may contain multiple windows.

Example:

```text
Main window
↓
Reservation window
↓
Customer window
```

Session 16 ViewHandler becomes more important.

Responsibilities:

```text
Load FXML
```

```text
Create Scene
```

```text
Switch windows
```

GUI structure remains organized.

---

## 13. One Controller per Window

Recommended structure:

```text
ReservationView.fxml
↓
ReservationViewController
```

Example:

```text
CustomerView.fxml
↓
CustomerViewController
```

Responsibility remains localized.

Avoid:

```text
One controller handles entire application
```

Small responsibilities improve design.

---

## 14. GUI and Model Separation

Good structure:

```text
GUI
↓
Controller
↓
Model Interface
↓
ModelManager
↓
Model Objects
```

Good separation improves:

- readability
- maintenance
- testing

Object-oriented responsibility still matters.

---

## 15. Events and Object Collaboration

Objects collaborate.

Example:

Controller:

```text
Receives event
```

Model:

```text
Updates state
```

GUI:

```text
Displays state
```

No single object should do everything.

Collaboration remains central.

---

## 16. Typical Beginner Mistakes

Common mistakes:

1. Putting domain logic inside controller
2. Making controllers too large
3. Accessing model internals directly
4. Ignoring interfaces
5. One controller for everything
6. GUI searching collections itself
7. Mixing GUI and domain responsibility
