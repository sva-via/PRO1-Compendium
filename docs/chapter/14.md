# Chapter 14 – Interfaces

## 1. Introduction

Session 14 introduces interfaces.

Inheritance introduced:

> "is-a"

relationships.

Interfaces introduce another important design mechanism:

> abstraction through contracts

Interfaces help objects collaborate while reducing coupling between classes.

The focus is on:

- interfaces
- contracts
- abstraction
- loose coupling
- replacing implementations
- responsibility
- application structure

Interfaces are an important tool for designing maintainable object-oriented systems.

---

## 2. What Is an Interface?

An interface specifies:

> what an object can do

without specifying:

> how it does it

Example:

```java
public interface Model
{
  Customer getCustomer(String phone);

  Vehicle getVehicle(
      String registrationNumber);

  void reserve(
      Vehicle vehicle,
      Customer customer,
      LocalDate from,
      LocalDate to);
}
```

The interface specifies:

- method names
- parameters
- return types

The implementation comes later.

---

## 3. Interface as Contract

An interface is a contract.

Example:

```text
Model
```

The contract says:

```text
Objects implementing Model
must provide these methods.
```

Users of the interface only need to know:

- what methods exist
- what the methods do

Not:

- internal implementation
- data structures
- storage details

---

## 4. Implementing an Interface

Classes implement interfaces.

Example:

```java
public class ModelManager
    implements Model
{
}
```

Keyword:

```java
implements
```

means:

> ModelManager is a Model

The class promises to implement all methods.

---

## 5. Example Implementation

Interface:

```java
public interface Model
{
  Customer getCustomer(
      String phone);
}
```

Implementation:

```java
public class ModelManager
    implements Model
{
  @Override
  public Customer getCustomer(
      String phone)
  {
    // implementation
  }
}
```

The interface specifies responsibility.

The implementing class performs the work.

---

## 6. @Override

Example:

```java
@Override
public Customer getCustomer(
    String phone)
{
}
```

`@Override` tells Java:

> This method implements or overrides another method.

Advantages:

- catches spelling mistakes
- improves readability
- makes intention clear

Use `@Override` consistently.

---

## 7. Interface Methods

Interface methods are by definition:

```text
public
abstract
```

Example:

```java
public interface Model
{
  Vehicle getVehicle(
      String registrationNumber);
}
```

No method body:

```java
{
}
```

No implementation.

Only specification.

---

## 8. Abstraction

Interfaces support abstraction.

Example:

View:

```text
Needs customer data
```

The View should not know:

- files
- database
- collections
- internal model structure

The View only needs:

```text
Model
```

Interface abstraction hides implementation details.

---

## 9. Loose Coupling

Interfaces reduce coupling.

Without interface:

```text
View
 ↓
ModelManager
```

Strong dependency.

With interface:

```text
View
 ↓
Model
 ↓
ModelManager
```

The View depends only on:

```text
Model
```

not:

```text
ModelManager
```

Loose coupling improves maintainability.

---

## 10. Replacing Implementations

Example:

Version 1:

```text
TextFilePersistence
```

Version 2:

```text
JsonPersistence
```

Version 3:

```text
DatabasePersistence
```

If all implement:

```text
Persistence
```

other classes may remain unchanged.

Interfaces make replacement easier.

---

## 11. Application Structure

Example conceptual structure:

```text
View
 ↓
Model Interface
 ↓
ModelManager
 ↓
Persistence Interface
 ↓
Persistence Implementation
```

Responsibilities:

### View

Responsible for:

- presenting data
- user interaction

---

### Model Interface

Responsible for:

- contract
- exposing required operations

---

### ModelManager

Responsible for:

- model coordination
- updating objects
- synchronization

---

### Persistence Interface

Responsible for:

- saving contract
- loading contract

---

### Persistence Implementation

Responsible for:

- actual file handling
- conversion
- storage format

Responsibility remains important.

---

## 12. Interface and Responsibility

Good design:

```text
View
```

knows:

```text
Model
```

Not:

```text
TextFilePersistence
```

Good design separates responsibilities.

Objects should know only what they need.

---

## 13. Multiple Interfaces

Java allows:

```java
extends
```

only once.

Example:

Legal:

```java
class Car
    extends Vehicle
```

Illegal:

```java
class Car
    extends Vehicle,
            Product
```

Java supports single inheritance.

Interfaces solve this limitation.

Example:

```java
public class ModelManager
    implements Model,
               Persistence
{
}
```

A class may implement multiple interfaces.

---

## 14. Interface versus Inheritance

Inheritance:

```text
is-a
```

Example:

```text
Car is a Vehicle
```

Interface:

```text
can-do
```

Example:

```text
ModelManager implements Model
```

Inheritance:

- specialization

Interface:

- capability
- abstraction
- contract

Both are important.

---

## 15. Example: Persistence Interface

Example:

```java
public interface Persistence
{
  void save();

  void load();
}
```

Implementation:

```java
public class TextFilePersistence
    implements Persistence
{
}
```

Alternative:

```java
public class JsonPersistence
    implements Persistence
{
}
```

The rest of the system stays unchanged.

Advantages:

- loose coupling
- easier maintenance
- easier replacement
- clearer responsibility
- better architecture

Interfaces support scalable design.

## 17. Testing with Interfaces

Interfaces simplify testing.

Example:

Reference:

```java
Model model;
```

Possible implementation:

```java
ModelManager
```

Alternative test implementation:

```java
FakeModel
```

Interfaces make systems easier to isolate and test.
