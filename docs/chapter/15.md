# Chapter 15 – File Persistence

## 1. Introduction

Session 15 introduces persistence.

Persistence means:

> saving data so it can be loaded again later.

Until now, objects only existed while the program was running.

When the program closes:

```text
Objects disappear
```

Persistence allows objects to survive beyond program execution.

The focus is on:

- persistence
- saving objects
- loading objects
- file formats
- exceptions
- interfaces
- separation of responsibility
- JSON persistence

Persistence becomes an important part of building realistic applications.

---

## 2. What Is Persistence?

Persistence means storing data permanently.

Examples:

```text
Notebook application
```

Without persistence:

```text
Program closes
→ Notes disappear
```

With persistence:

```text
Program closes
→ Notes saved to file
→ Notes loaded next time
```

Persistence gives applications memory.

---

## 3. Responsibility and Persistence

Objects should still have clear responsibility.

Example:

```text
Notebook
```

Responsible for:

- notes
- adding notes
- removing notes

Not responsible for:

- reading files
- writing files

Saving belongs elsewhere.

Good object-oriented design separates responsibilities.

---

## 4. Persistence Interface

Example:

```java
public interface NotebookPersistence
{
  void save(Notebook notebook);

  Notebook load();
}
```

The interface specifies:

- what persistence can do

Not:

- how persistence works

Interfaces support abstraction.

---

## 5. Implementation Example

Example:

```java
public class
JsonFileNotebookPersistence
    implements NotebookPersistence
{
}
```

Keyword:

```java
implements
```

means:

> This class fulfills the persistence contract.

Implementation handles:

- file reading
- file writing
- conversion

The model remains separate.

---

## 6. Saving Data

Example:

```java
@Override
public void save(Notebook notebook)
{
  try
  {
    parser.toJsonFile(
        notebook,
        fileName);
  }
  catch (ParserException e)
  {
    throw new PersistenceException(
        "Could not save notebook", e);
  }
}
```

Responsibility:

```text
Convert object → file
```

The Notebook itself remains unchanged.

---

## 7. Loading Data

Example:

```java
@Override
public Notebook load()
{
  try
  {
    Notebook notebook =
        parser.fromJsonFile(
            fileName,
            Notebook.class);

    return notebook;
  }
  catch (ParserException e)
  {
    throw new PersistenceException(
        "Could not load notebook", e);
  }
}
```

Responsibility:

```text
File → object
```

Persistence reconstructs object state.

## 8. JSON Format

JSON stands for:

```text
JavaScript Object Notation
```

Example:

```json
{
  "notes":
  [
    {
      "note":"Check Facebook",
      "highPriority":false
    },
    {
      "note":"Make PRO1 exercises",
      "highPriority":true
    }
  ]
}
```

JSON is:

- structured
- readable
- widely used

JSON is often suitable for object persistence.

---

## 9. JSON and Objects

Objects become structured file data.

Example object:

```text
PriorityNote
```

Fields:

```text
note
highPriority
```

JSON:

```json
{
  "note":"Check Facebook",
  "highPriority":false
}
```

Persistence converts:

```text
Object → JSON
```

and later:

```text
JSON → Object
```

## 10. Exceptions and Persistence

File operations may fail.

Examples:

- missing file
- invalid file format
- parser problems

Persistence should communicate problems clearly.

Example:

```java
throw new PersistenceException(
    "Could not load notebook", e);
```

Responsibility:

```text
Detect problems
→ communicate problems
```

Exceptions remain important.

---

## 11. Testing Persistence

Persistence should be tested.

Example:

```java
@Test
void testJsonParserPersistence()
{
  Notebook notebook =
      createNotebook();

  NotebookPersistence
      persistence =
      new JsonFileNotebookPersistence(
          "notebook.json");

  assertDoesNotThrow(
      () -> persistence.save(notebook));

  Notebook loaded =
      assertDoesNotThrow(
          () -> persistence.load());

  checkValidLoadedNotebook(
      notebook, loaded);
}
```

Tests verify:

- saving works
- loading works
- data survives correctly

Persistence requires testing.

## 12. File Formats

Different persistence approaches exist.

---

### Text File

Example:

```text
Bob;3;bob@email.com
```

Advantages:

- simple
- readable
- editable

Disadvantages:

- manual parsing
- maintenance effort

---

### Binary File

Advantages:

- automatic object storage

Disadvantages:

- difficult to inspect
- class changes may break compatibility

---

### JSON

Advantages:

- readable
- structured
- library support
- integration friendly

Disadvantages:

- may expose implementation details

Choose based on responsibility and requirements.


```text
Application
```

The application remains unchanged.

Interfaces reduce coupling.

---

## 14. Persistence and Inheritance

Inheritance introduces additional complexity.

Example:

Vehicle hierarchy:

```text
Vehicle
├── Car
└── Bicycle
```

JSON:

```json
{
 "owner":"Bob",
 "price":200,
 "regNo":"AB12345"
}
```

Problem:

When loading:

```text
Parser only sees Vehicle
```

Which subclass should be created?

Persistence must preserve type information.

---

## 15. Polymorphic Persistence

Example:

```java
parser.registerPolymorphicAdapter(
    Vehicle.class,
    List.of(
       Car.class,
       Bicycle.class));
```

The parser learns:

```text
Vehicle may become:

Car
Bicycle
```

Type information becomes important.

---

## 16. Additional JSON Information

Example:

```json
{
 "owner":"Bob",
 "price":200,
 "class-type":"Car"
}
```

Now loading can reconstruct:

```text
Vehicle → Car
```

Persistence sometimes requires extra information.

---

## 17. Separation of Responsibility

Good design:

Notebook:

```text
Manages notes
```

Persistence:

```text
Manages files
```

Parser:

```text
Converts formats
```

Responsibility remains central.

Objects should do one thing well.

5. Forgetting persistence tests
6. Ignoring inheritance complexity
7. Tight coupling to file format
