# Chapter 9 – ArrayList

## 1. Introduction

Session 9 introduces `ArrayList`.

`ArrayList` is a collection class that stores objects dynamically.

The focus is on:

- `ArrayList`
- dynamic collections
- collections of objects
- wrapper classes
- adding and removing elements
- converting between arrays and collections

`ArrayList` solves many of the limitations of arrays.

---

## 2. Why ArrayList?

Arrays have fixed size.

Example:

```java
private int[] grades;
```

Once the array is full, a larger array must be created manually.

`ArrayList` handles resizing automatically.

Example:

```java
private ArrayList<Integer> grades;
```

Advantages:
- dynamic size
- simpler code
- easier insertion and removal

---

## 3. Importing ArrayList

`ArrayList` belongs to the Java Collections Framework.

Example:

```java
import java.util.ArrayList;
```

The import statement is required before using the class.

---

## 4. Creating an ArrayList

Example:

```java
ArrayList<Integer> grades;
```

The collection object must be created.

Example:

```java
grades = new ArrayList<Integer>();
```

A common pattern:

```java
private ArrayList<Integer> grades;

public GradeList()
{
  grades = new ArrayList<Integer>();
}
```

---

## 5. Generic Types

`ArrayList` stores a specific type.

Example:

```java
ArrayList<String>
ArrayList<Person>
ArrayList<Integer>
```

The type inside `< >` specifies which objects may be stored.

This improves type safety.

---

## 6. Wrapper Classes

`ArrayList` stores objects, not primitive types.

Primitive types therefore use wrapper classes.

Examples:

| Primitive | Wrapper Class |
|---|---|
| `int` | `Integer` |
| `double` | `Double` |
| `char` | `Character` |
| `boolean` | `Boolean` |

Example:

```java
ArrayList<Integer> grades;
```

instead of:

```java
ArrayList<int>
```

which is illegal.

---

## 7. Adding Elements

Elements are added using `add()`.

Example:

```java
grades.add(12);
grades.add(7);
grades.add(10);
```

The collection automatically grows when necessary.

No manual resizing is needed.

---

## 8. Accessing Elements

Elements are accessed using `get()`.

Example:

```java
int grade = grades.get(0);
```

Indexes still start at `0`.

Example:

```text
Index:   0   1   2
Value:  12   7  10
```

---

## 9. Replacing Elements

Elements can be replaced using `set()`.

Example:

```java
grades.set(1, 4);
```

The element at index `1` becomes `4`.

---

## 10. Removing Elements

Elements can be removed using `remove()`.

Example:

```java
grades.remove(1);
```

Removing an element shifts later elements automatically.

This is simpler than manual array shifting.

---

## 11. Collection Size

`ArrayList` stores its own size.

Example:

```java
grades.size()
```

Important:
- `size()` is a method
- arrays use `length`

Example:

```java
grades.size()
```

versus:

```java
array.length
```

---

## 12. Traversing an ArrayList

Collections are often traversed using loops.

### Indexed for Loop

Example:

```java
for (int i = 0; i < grades.size(); i++)
{
  System.out.println(grades.get(i));
}
```

### Enhanced for Loop

Example:

```java
for (int grade : grades)
{
  System.out.println(grade);
}
```

After Session 8 and 9:
- use enhanced `for` loops when indexes are unnecessary
- use indexed loops when indexes are needed

---

## 13. Collections of Objects

`ArrayList` is especially useful for storing objects.

Example:

```java
private ArrayList<Person> persons;
```

Objects can be added:

```java
persons.add(new Person("Bob"));
persons.add(new Person("Ada"));
```

The collection stores references to objects.

---

## 14. Searching in Collections

Loops can search collections.

Example:

```java
public Person findPerson(String name)
{
  for (Person person : persons)
  {
    if (person.getName().equals(name))
    {
      return person;
    }
  }

  return null;
}
```

Collections are often traversed when searching.

---

## 15. Removing Objects

Objects can be removed directly.

Example:

```java
persons.remove(person);
```

Or by index:

```java
persons.remove(0);
```

The collection reorganizes itself automatically.

---

## 16. ArrayList and Responsibility

The collection should usually be private.

Example:

```java
private ArrayList<Person> persons;
```

Other classes should not manipulate the collection directly.

Good design:

```java
personList.addPerson(person)
```

instead of exposing the internal collection.

The class should manage:

- adding
- removing
- searching
- validation

---

## 17. toArray()

An `ArrayList` can be converted to an array.

Example:

```java
Person[] array = persons.toArray(new Person[0]);
```

This creates an array containing the collection elements.

Session 9 introduces simple conversion between collections and arrays.

---

## 18. Empty Collections

Collections may be empty.

Example:

```java
if (persons.isEmpty())
{
  // no persons stored
}
```

Example:

```java
persons.size() == 0
```

Both approaches can be used.

---

## 19. ArrayList vs Arrays

### Arrays

Advantages:

- simple
- fixed-size structures
- direct storage

Disadvantages:

- fixed capacity
- manual resizing
- manual shifting

### ArrayList

Advantages:

- dynamic size
- automatic resizing
- simpler insertion and removal

Disadvantages:

- slightly more overhead
- stores objects only

After Session 9:

- prefer `ArrayList` when size changes dynamically
- use arrays when fixed size is intentional

## 20. Testing Collection Classes

Collection behavior should be tested carefully.

Example:

```java
@Test void addPerson()
{
  PersonList list = new PersonList();
  Person person = new Person("Bob");

  list.addPerson(person);

  assertEquals(1, list.size());
}
```

Important test cases include:

- adding elements
- removing elements
- searching
- empty collections
- boundary indexes

## 21. Typical Beginner Mistakes

Common mistakes:

1. Forgetting to create the collection with `new`
2. Using primitive types instead of wrapper classes
3. Confusing `size()` and `length`
4. Accessing illegal indexes
5. Exposing the internal collection directly
6. Forgetting that collections store references
7. Using indexed loops when enhanced `for` loops are simpler
