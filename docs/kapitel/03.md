# Kapitel 3 – Validering og exception

## 1. Problemet

I den første version af `Name` kunne vi oprette objekter som:

```java
new Name("", "");
new Name(null, "Lovelace");
```

Disse objekter giver ikke mening.

Problemet er, at klassen ikke beskytter sin egen tilstand.

---

## 2. Løsningen: validering i konstruktøren

Vi skal sikre, at objektet **altid er gyldigt**.

Det gør vi i konstruktøren ved at kontrollere input.

---

## 3. Opdateret klasse

```java
public class Name
{
  private String firstName;
  private String lastName;

  public Name(String firstName, String lastName)
  {
    if (firstName == null || firstName.isBlank())
    {
      throw new IllegalArgumentException("First name cannot be empty");
    }

    if (lastName == null || lastName.isBlank())
    {
      throw new IllegalArgumentException("Last name cannot be empty");
    }

    this.firstName = firstName;
    this.lastName = lastName;
  }

  public String getFullName()
  {
    return firstName + " " + lastName;
  }
}
```

---

## 4. Hvad er en exception?

En exception er en måde at sige:

> “Dette input er ikke gyldigt – objektet kan ikke oprettes”

Det er ikke en fejl i programmet, men en måde at beskytte objektets regler på.

---

## 5. Kontrakt (nu opfyldt)

Nu gælder altid:

- firstName er ikke null
- firstName er ikke tom
- lastName er ikke null
- lastName er ikke tom

Klassen sikrer nu sin egen invariant.

---

## 6. Test af exception

Vi kan teste ugyldige input med JUnit:

```java
@Test
void contructor_throwsException_onEmptyFirstname()
{
  assertThrows(IllegalArgumentException.class,
      () -> new Name("", "Lovelace"));
}
```

---

## 7. Testidéer

### Gyldige input
- ("Ada", "Lovelace")

### Grænsetilfælde
- ét bogstav
- navne med mellemrum

### Ugyldige input
- "", "Lovelace"
- null, "Lovelace"
- "Ada", null

---

## 8. Designprincip

En vigtig regel:

> En klasse skal selv sikre, at den altid er i en gyldig tilstand.

Det betyder:
- vi validerer input i konstruktøren
- vi afviser ugyldige værdier med exception

---

1. Hvorfor skal validering ske i konstruktøren?

3. Hvad sker der, hvis vi ikke bruger exception?

## Afslutning

Vi har nu:

- indført validering
- sikret klassens invariant
- brugt exception til at beskytte objektet
- testet både gyldige og ugyldige tilfælde

Dette er en central del af objektorienteret design:

Et objekt er kun værdifuldt, hvis det altid er i en gyldig tilstand.
