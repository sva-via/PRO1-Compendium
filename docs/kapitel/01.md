# Kapitel 1 – Hvad er et objekt?

## 1. Introduktion

Dette kapitel handler om det mest grundlæggende spørgsmål i objektorienteret programmering: Hvad er et objekt?

I PRO1 er målet ikke at lære Java som sprog, men at lære at modellere virkeligheden i software. Et objekt er ikke blot en teknisk konstruktion – det er en model af et begreb fra et domæne.

Vi begynder derfor ikke med syntaks, men med forståelse:

- Hvad er forskellen på en variabel og et objekt?
- Hvad betyder det, at en klasse modellerer et begreb?
- Hvad er state og adfærd?


## 2. Objekt vs. variabel

En variabel er et sted i programmet, hvor vi gemmer en værdi.

`double celsius = 20.5;`

Her gemmer variablen `celsius` tallet 20.5.

Men en variabel er ikke et begreb. Den er kun en beholder.

Et objekt derimod repræsenterer noget med:

- En tilstand (state)
- En adfærd (metoder)
- Et ansvar

`Temperature t1 = new Temperature(20.5);`

Her er `t1` en variabel – en reference til et `Temperature`-objekt, mens objektet er instansen af `Temperature`.

En variabel er et navn i programmet, som giver adgang til et objekt.
Objektet er den instans, der repræsenterer et begreb og indeholder både state og adfærd.

## 3. Klassen som model af et begreb

En klasse beskriver, hvordan objekter af en bestemt type ser ud og opfører sig.

```
public class Temperature
{
  private double celsius;

  public Temperature(double celsius)
  {
    this.celsius = celsius;
  }

  public double getCelsius()
  {
    return celsius;
  }

  public double getFahrenheit()
  {
    return celsius * 9 / 5 + 32;
  }
}
```

Klassen modellerer begrebet temperatur. Den indeholder state og adfærd og afgrænser sit ansvar.

## 4. State og adfærd

State er de data, objektet indeholder.
Adfærd er det, objektet kan gøre.

State i `Temperatue`:

`private double celsius;`

Adfærd:
```
  public double getCelsius()
  {
    return celsius;
  }

  public double getFahrenheit()
  {
    return celsius * 9 / 5 + 32;
  }
```
Adfærd bør være relateret til objektets begreb.

## 5. Hvad er en invariant?

En invariant er en regel om objektets tilstand, som altid skal være opfyldt efter konstruktion og efter enhver offentlig metode. Det er altså det, der altid skal være sandt for et objekt.

For en temperatur i celsius må det gælde at den aldrig er mindre end -273,15.

Objektet skal beskytte sig selv, så derfor vil vi sikre ved oprettelse at invariansen bevares - at der ikke brydes regler. Oprettelsen af et objekt sker ved at kalde konstruktøren og derfor skal der her foretages tjek på valid input.

```
public class Temperature
{
  private double celsius;

  public Temperature(double celsius)
  {
    if (celsius < -273.15)
    {
      throw new IllegalArgumentException("Below absolute zero");
    }
    this.celsius = celsius;
  }

  public double getCelsius()
  {
    return celsius;
  }

  public double getFahrenheit()
  {
    return celsius * 9 / 5 + 32;
  }
}
```
Her bruges `IllegalArgumentException` til at afvise input, der bryder invarianten.

Invariant er et centralt begreb i objektorienteret design og vil blive brugt gennem hele kurset.

## 6. Designovervejelser

Hvorfor lave en klasse?

- Samler relaterede data
- Giver begrebet identitet
- Kontrollerer korrekt brug

Alternativet med løse variabler giver ingen samlet struktur eller ansvar.

## 7. Typiske fejl og misforståelser

1. At tro at objekt = variabel
2. At placere adfærd uden for objektet
3. At lade klassen gøre for meget

Et objekt bør repræsentere ét begreb med klart ansvar.

## Afslutning

Et objekt er ikke blot en datastruktur.

Det er:

- En model af et begreb
- En samling af state
- En enhed med ansvar
- En aktør med adfærd

At programmere objektorienteret betyder derfor ikke primært at skrive metoder.

Det betyder at træffe designbeslutninger om:

- Hvilke begreber findes i domænet?
- Hvad er deres ansvar?
- Hvordan skal de samarbejde?

Resten af kurset bygger på denne forståelse.
