# Kapitel 2 – Første klasse: Name

## 1. Introduktion

Vi laver nu vores første klasse: `Name`.

Formålet er at modellere et navn med:
- fornavn
- efternavn

Vi arbejder videre med idéen fra kapitel 1:
- en klasse modellerer et begreb
- objektet skal være i en gyldig tilstand
- vi skal kunne teste vores design

---

## 2. Klassen

```java
public class Name
{
  private String firstName;
  private String lastName;

  public Name(String firstName, String lastName)
  {
    this.firstName = firstName;
    this.lastName = lastName;
  }

  public String getFullName()
  {
    return firstName + " " + lastName;
  }
}
```

---

## 3. Hvad modellerer klassen?

Klassen `Name` modellerer et navn som et begreb.

Et objekt har:

**State**
- firstName
- lastName

**Adfærd**
- getFullName()

---

## 4. Første version – uden regler

I denne version accepterer konstruktøren alle værdier:

```java
new Name("", "");
new Name(null, "Lovelace");
```

Det betyder, at vi kan lave objekter, der ikke giver mening.

👉 Klassen håndhæver endnu ingen regler.

---

## 5. Hvad bør være sandt? (kontrakt)

Vi kan formulere klassens kontrakt:

- firstName må ikke være null
- firstName må ikke være tom
- lastName må ikke være null
- lastName må ikke være tom

Dette er klassens **invariant**.

Lige nu bliver den ikke håndhævet.

---

## 6. Testidéer

Inden vi retter klassen, kan vi tænke i tests.

### Normale tilfælde
- ("Ada", "Lovelace") → "Ada Lovelace"

### Grænsetilfælde
- ét bogstav
- mellemrum i navne

### Ugyldige input
- null
- tom streng

---

## 7. Første JUnit-test

```java
@Test
void fullName_isCombinedCorrectly()
{
  Name name = new Name("Ada", "Lovelace");
  assertEquals("Ada Lovelace", name.getFullName());
}
```

Denne test verificerer normal adfærd.

---

## 8. Hvad mangler?

Spørg dig selv:

- Kan vi stole på objektet?
- Kan det være i en ugyldig tilstand?
- Hvad sker der ved null?

👉 Svaret er: Klassen beskytter ikke sig selv endnu.

---

## 9. Designprincip

En vigtig regel:

> En klasse bør selv sikre, at den altid er i en gyldig tilstand.

Det betyder:
- vi må ikke acceptere alle input
- vi skal afvise ugyldige værdier

---

## 10. Refleksionsspørgsmål

1. Hvad repræsenterer et Name-objekt?
2. Hvilke regler bør gælde for et navn?
3. Hvad sker der, hvis vi ikke validerer input?
4. Hvilke tests mangler vi endnu?

## Afslutning

Vi har nu lavet en første version af en klasse, der modellerer et begreb.

Men:

- Klassen håndhæver ikke sin kontrakt
- Objektet kan være i en ugyldig tilstand
- Vi mangler validering

I næste kapitel løser vi dette ved hjælp af **validering og exception**.
